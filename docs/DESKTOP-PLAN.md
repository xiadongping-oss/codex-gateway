# Codex Gateway 桌面版实施计划

更新日期：2026-10-31。首版采用 Tauri 2、现有 Vue 3/Vite、随包 Node.js 和现有网关，正式交付 Windows x64、macOS ARM64 和 macOS x64 客户端。先解决程序只读、数据持久化和进程生命周期，再验证双端业务闭环，最后完成界面扩展与正式发行。

执行状态和任务依赖统一记录在 [桌面版任务清单](DESKTOP-TASKS.md)。Windows 未签名 NSIS / ZIP 内部预览已实现，正式发行验收继续按任务清单推进；构建操作见 [发行指南](RELEASE.md)。

工作台统一采用紫色设计体系，导航、功能分区、图标与内容规范见 [工作台设计规范 v1](DESKTOP-DESIGN.md)。日常业务、服务诊断、数据备份和应用偏好采用同一套工作台导航；首次配置、停机与故障状态继续可用。

A04 已固定 [桌面控制协议 v1](DESKTOP-CONTROL.md) 和 [桌面数据目录 v1](DESKTOP-DATA.md)。后续 F03/F04 与桌面集成以这两份契约的字段、状态和兼容规则为准；契约完成不代表运行实现已完成。

## 首版范围

用户安装后无需另装 Node、Rust 或开发工具，可以登录账号、配置 API Key、调用模型、使用 MCP 和图片素材功能。关闭窗口后应用驻留托盘；选择退出后停止网关及其所有子进程。升级保留账号、密钥、配置、图片和调用记录。

| 项目 | 首版约定 |
|---|---|
| Windows | x64 NSIS 安装包，另提供 ZIP；包含 WebView2 检测和缺失处理 |
| macOS | ARM64、x64 分别构建 DMG，完成签名、公证与安装验证 |
| 业务能力 | 保留现有多账号、OAuth、OpenAI 兼容 API、MCP、图片与局域网接入 |
| 界面 | 按工作台设计规范统一紫色主题、分组导航、功能分页、反馈与原创图标；说明按需展开 |
| 更新 | 首版提供发布版本信息、手动下载安装和保留数据的覆盖升级 |
| 自启动 | 可选的用户登录后启动，默认关闭；不引入新的系统级常驻服务 |
| 首版之外 | 自动更新、Linux 桌面安装包、Windows ARM64、移动端、云同步、可拖拽仪表盘 |

最低系统版本在工具链与双端验证后锁定。候选测试基线为 Windows 11 x64、macOS 13 及以上；这不是已验证支持承诺。是否补充 Windows 10 需单独记录测试环境和维护成本。首版发布日期在最小闭环通过后估算。

## 技术决策

### 桌面外壳与界面

Tauri 负责窗口、托盘、单实例、系统浏览器、安装集成及网关进程管理。Node 继续处理业务与前端静态资源，Vue 继续通过同源 HTTP 访问网关。首版不把业务迁移到 Rust，不将界面重写为 Flutter。

主窗口先展示随包的本地启动页。桌面壳通过私有进程通道确认网关身份和就绪状态，再加载本机控制台的一次性登录入口，沿用 HttpOnly 管理会话。长期管理令牌不传入页面、不放 URL、不写普通日志；不能仅凭端口存在或 `/health` 成功判断目标进程可信。

业务页面默认没有原生执行权限。确需原生能力时，为明确的窗口、来源和操作设置最小授权；不向本机 HTTP 页面开放通用 shell、任意文件读写或任意 URL 打开。OAuth 与外部链接在系统浏览器打开，应用内页面仅导航到受控的本机来源。

新增目录建议为 `desktop/`，包含 Tauri 工程、启动页和资源组装配置；继续复用 `frontend/` 的构建结果及 `gateway/` 源码。公共资源准备逻辑由新旧发行入口共享，保留现有脚本启动方式。

### 安装器与视觉风格

采用 Material You 方向的色彩、圆角和状态反馈，独立实现 Vue 组件，使用项目自己的品牌与资源。FlClash 作为设计参考，不直接移植其 Flutter 代码或品牌素材。

Windows 首版继续选择 Tauri 原生支持的 NSIS，定制图标、向导图和文案。Inno Setup 同款安装向导作为备选：只有明确需要该外观时再切换，同时承担自定义打包、WebView2 安装、卸载和更新集成工作。macOS 沿用 DMG 拖入 Applications 的安装方式。

### 程序资源与用户数据

| 内容 | 约定 |
|---|---|
| 程序资源 | Node、网关代码、已固化的依赖、前端构建结果只读；通过绝对路径定位 |
| Windows 数据 | `%LOCALAPPDATA%\CodexGateway`，兼容现有安装布局 |
| macOS 数据 | `~/Library/Application Support/CodexGateway` |
| 桌面 ZIP | 默认使用用户数据目录；随盘保存数据只能通过显式便携选项开启 |
| 源码运行与旧 ZIP | 默认 legacy，保留原有 `CGW_DATA_DIR` 解析和图库行为；managed 显式启用，不自动迁移 |
| 生成图片 | 网关、bridge、素材列表、MCP 与索引使用同一解析入口，不以改变整个 HOME 的方式重定向 |
| 外部素材 | 保留用户选择的素材源路径，不擅自复制或迁移外部目录 |

迁移从明确的旧安装或用户选定目录读取。停写后备份、复制、校验，再写入迁移完成标记；失败保留旧数据和恢复入口。重复执行不得重复导入账号或覆盖新数据。旧共享图库保留兼容读取或明确迁移策略，避免破坏其他仍在使用该目录的程序。

卸载默认保留用户数据。若提供清除数据选项，须单独明示且默认不选中。构建和验证仅使用临时测试数据，发行包中禁止包含账号、令牌、日志和机器本地路径。

### 网关生命周期

区分两个操作：控制台的启停管理 bridge 业务实例；桌面托盘的“退出”管理 Tauri、Node 启动器及全部后代进程。界面文案和测试都要遵循该边界。

| 场景 | 目标行为 |
|---|---|
| 首次启动 | 准备数据目录、启动随包 Node、身份握手、等待控制台就绪 |
| 重复启动桌面 | 激活已有窗口，不重复启动网关 |
| 关闭窗口 | 隐藏窗口并保持托盘与网关运行，在桌面管理页和托盘提示中说明退出入口 |
| 主动退出 | 拒绝新业务请求、等待在途任务、刷盘、停 bridge、停 Node，再退出桌面壳 |
| 超时退出 | 排空预算 30 秒，超时提供继续等待或结束；随后收尾最多 5 秒，壳额外确认实际退出最多 2 秒；异常结果阻断正常升级 |
| Node 崩溃 | 清理所属进程后有限退避重启，默认 5 分钟最多 3 次；随后显示恢复与日志入口 |
| 桌面壳崩溃 | Node 通过私有通道断开感知退出；平台进程管理机制兜底清理后代 |
| 端口冲突 | 保持默认公共端口 4173，不静默换端口；允许明确配置新端口并展示新的接入地址 |
| 已有脚本服务 | 验证身份与数据目录；首版提示从原入口停止再启动桌面，不自动接管或杀死未知进程 |
| 系统关机 | 尽力刷盘和清理，下次启动执行一致性检查，不依赖无限等待 |

私有控制协议至少覆盖就绪、身份挑战响应、退出、错误与协议版本；业务日志与控制消息分流。Windows 验证 Job Object 等进程树管理方案；macOS 验证进程组、父进程通道和 bridge 后代退出策略。不能把 Unix 信号或单个 PID 的终止当作完整的跨平台退出方案。

A04 选定 Node stdin/stdout 专用管道传输控制帧、stderr 输出日志；壳按子进程句柄与本次挑战验证身份，再申请实例绑定的一次性登录入口。握手、命令与退出状态以 [控制协议](DESKTOP-CONTROL.md) 为准；stdio MCP 使用独立进程，不复用这条管道。

### 构建与更新

按 `win32/x64`、`darwin/arm64`、`darwin/x64` 分别锁定 Node 版本、来源和 SHA-256。锁定目标依据发行目标而不是构建机平台；记录缺失或校验不符立即失败。Node 具体版本在兼容与维护状态核对后选定，不能直接沿用当前 Windows 指纹作为 Mac 运行时。

Windows 构建安装包并验证签名流程。macOS 在 Mac 或 macOS CI 上构建，检查所有内置可执行文件的签名与所需权限，完成 Developer ID 签名、公证和票据装订。对 Node 的实际运行和业务调用做签名后验证。构建成功不等于实际安装通过。

程序版本、Node、依赖和前端一起发行，不单独热替换网关代码。升级前记录数据格式版本并备份；若格式不支持旧版，明确阻止不兼容降级，恢复采用匹配版本的程序与数据备份。自动更新后续再接入，其签名与操作系统代码签名分别管理。

## 验证矩阵

所有场景分别记录 Windows x64、macOS ARM64、macOS x64 的结果、系统版本、程序版本与证据位置。未测试必须标为未测试，不以一个架构的结果代替另一个架构。

| 场景 | 验收要点 |
|---|---|
| 干净安装 | 无 Node/Rust 的机器可启动；Windows 缺少 WebView2 时可正确处理；Mac 从下载的 DMG 安装并通过系统检查 |
| 登录与鉴权 | OAuth 回调、取消、超时、再次登录；桌面管理会话与系统浏览器分离；无凭据的控制请求仍拒绝 |
| 业务 | 流式文本、工具调用、图片生成/下载、MCP、账号切换、API Key 与 LAN 隔离 |
| 资源只读 | 启动、登录、调用、日志、图片均不改程序包；签名后资源保持一致 |
| 目录 | 带空格和中文的路径、从任意工作目录启动、旧图库及账号迁移、只读或磁盘写入失败 |
| 进程 | 连续启停 20 次、重复启动、端口被占、壳与 Node 分别崩溃、退出后无所属后代与残留监听 |
| 桌面交互 | 托盘恢复、窗口关闭、主题记忆、键盘焦点、文本/图片剪贴板、文件保存 |
| 升级与恢复 | 旧 ZIP 和安装版迁移、覆盖升级、迁移中断重试、数据保留卸载、备份恢复 |
| 稳定性 | 至少 8 小时运行、睡眠唤醒、断网恢复、代理切换、日志增长；记录空闲和业务峰值资源占用 |

测试按变更范围执行：前端构建与浏览器检查；补丁、账号与实例池相关单元测试；目录及控制协议的新增专项测试；发行脚本改动执行已有构建与构建变异测试。现有 Unix 服务脚本测试作为回归依据，不能替代 macOS 桌面测试。测试命令与当前覆盖范围见根 `package.json` 和 [测试说明](../gateway/tests/README.md)。
