# v1.14.17

- 修复局域网用户调用生图技能时「后台超时、客户端提示用户已取消」：根因是客户端 MCP 工具请求默认只有 60 秒固定超时，且不会随网关的进度通知重置，而一次生图常需数分钟；文本对话走 `/v1/chat/completions`，不经 MCP，所以一直正常。
- 网关接入页 `/setup` 生成的 MCP 配置与 LAN 一键安装脚本现在写入 `"timeout": 420000`；首次配置、普通更新、换 Key 三种 Prompt 都要求保留或补齐该值，已有更大的值不会被改小，自定义请求头与其他连接器保持不变。
- 客户端断开后，网关 `/mcp` 只停止进度心跳，不再中断已受理的生图请求：任务继续完成并落盘到个人图库，调用日志单独标注「客户端已断开 · 生图继续执行」，避免结果丢失或被误判为失败。
- 内部生图等待上限由 300 秒统一提升到 400 秒（对齐上游 bridge），HTTP MCP、stdio MCP 与 Skill 文档同步；Skill 明确「超时或连接中断不等于用户取消，先检查个人图库再决定是否重试」。
- 一并合并未发布的 LAN 生图修正：改为意图触发，移除对话链路的原生生图注入，修复回环图片链接与调用日志收尾判定。
- **升级后局域网用户需重连 MCP**：重新运行接入页的「更新配置」Prompt，或在 `~/.workbuddy/mcp.json` 的网关条目里手工加入 `"timeout": 420000` 并重新加载连接器；否则旧的 60 秒超时仍然生效。
- 新增「客户端断开不丢图」端到端回归、MCP 配置超时契约与安装脚本变异体；完整测试闸门与前端产物确定性重建均通过。

本次提供 Windows x64 安装包、便携 ZIP、在线更新签名和 SHA-256 校验清单。
